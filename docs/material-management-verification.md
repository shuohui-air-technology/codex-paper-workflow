# 材料版本管理改进：本地验证记录

日期：2026-10-09。基线：GitHub `main` 的提交
`81efff9cbb65e04286ec5f73e0a8b450066cc0e9`。实现位于本地独立工作树
`work/material-version-index`，分支 `feat/material-version-index`；本轮没有
发布 GitHub、覆盖全局 Skill 安装或改动真实论文项目。

## 本轮改变了什么

- 在已有确认目录之上增加稳定材料角色及多候选、多文件登记。
- 根据内容哈希与布局识别新稿、修改、未变内容、历史内容和唯一迁移，
  不按文件名和日期决定当前版本。
- 增加只读恢复摘要、可保存的扫描范围、限量文本差异和批量确认。
- 保存扫描时持续记录已核验的候选迁移；恢复摘要不写登记状态。
- 为自定义流程增加按角色与目录版本登记已确认输入的命令，保持现有
  运行的输入冻结，并报告运行中版本与当前确认版本的不同。
- 同步 Skill 入口、中文用户指南、中英文 README 和实现合同。

`progress.md`、自定义执行状态、确认目录分别保留原有职责。材料登记
不增加第二个当前版本权威；阶段成果仍需要原来的证据检查。

## 验证场景

专项测试覆盖：只读恢复、登记幂等、明确确认、未变内容不重复确认、
哈希与文本差异、同名不同内容、完全相同的副本、唯一与歧义迁移、
多文件迁移后继续编辑、首次确认前的迁移、过期审阅与证据、批量准备
失败不提交、批量重试不新增版本、并发确认、历史恢复、快照损坏、
扫描范围与不完整扫描、路径穿越、链接及大小写派生目录、命令行进程
间接续、官方输出验收、自定义 `node-result-v2` 来源链及冻结输入。

独立审查最初复现了“迁移后继续编辑丢失候选身份”：只读识别移动后
没有持续保存路径关联。修复后，保存扫描更新工作关联，返回报告、
登记库与保存审阅的版本一致；后续在新路径编辑仍显示 `changed`，
而已确认快照及目录版本保持不变。对应操作已写入 Skill 和用户指南。

展示更新失败与确认提交分别报告。确认目录提交成功后，即使材料索引
展示刷新失败，也保留成功结果与 `material_index_pending`；重试相同
审阅不重复采纳，主动扫描可修复材料展示。

## 证据范围

本记录证明所列测试与独立 CLI 场景通过，不证明任意 Agent 都会遵守
Skill 入口。材料管理器可以拒绝过期审阅并核验确认快照；工作流外的
直接文件读取仍需执行者遵守声明的材料选择规则。文本差异是审阅辅助，
不代替论文科学内容、二进制图件或实验数据的验收。

扫描只覆盖声明范围并遵守文件数、内容大小及路径限制。不完整扫描
会报告；大型项目应使用具体范围。只读恢复不会持久化候选迁移，继续
编辑移动后的文件前需保存一次扫描。
