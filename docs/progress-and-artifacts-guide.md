# 进度与已确认产物使用指南

[返回文档导航](README.md) · [自定义工作流入门](workflow-studio-guide.md)

长时间推进一个论文项目时，需要同时回答两个问题：下一步做什么，以及现在应当使用哪一版成果。工作流用进度记录回答第一个问题，用已确认产物索引回答第二个问题。

日常使用仍通过 Codex 对话完成。你确认采用一份已经验收的成果后，工作流会保存它的内容快照，按产物类型更新当前版本展示，并保留旧版本。原来的草稿、试验文件和工作记录继续留在原处，供你修改或追溯。

## 一次正常的工作过程

1. 描述当前任务，Codex 先读取项目模式、当前进度和已确认产物索引，确定本次使用的材料版本。
2. 在工作文件上研究、写作或修改。草稿生成后，先完成该阶段要求的检查。
3. 查看成果并明确表示采用，例如：“确认采用这版文献比较表，作为接下来撰写引言的依据。”
4. 工作流登记这次确认，保存不可变快照并更新当前版本展示；随后由 Codex 单独更新进度，记录下一步需要做什么。
5. 后续确认新的版本时，对应产物的当前指向随之更新；旧版快照继续保留。

你无需手动填写 JSON、整理版本号或移动源文件。自定义阶段的成功回执证明一次任务执行及其产物已经登记；科学内容仍需完成相应检查，再由你决定是否采用。

官方流程确认产物时，工作流会核对当前进度版本和真实检查证据；自定义流程会关联当前运行中已提交的成功回执，核对具体产物及其内容版本。收录操作本身不修改“下一步”，因此确认产物和更新进度可以分别检查、重试。

官方进度标记有效性受阻时，需要先处理对应问题，再收录新的确认版本；已经确认且快照完整的成果仍可读取。

## 文件分别放在哪里

```text
论文项目/
├── 原有论文、文献、代码与工作目录/       # 继续编辑的原始工作文件
├── artifacts/
│   ├── INDEX.md                       # 当前已确认产物的阅读入口
│   └── current/
│       └── <type>/<artifact_id>/       # 按类型与产物标识展示当前确认版本
└── .research/
    ├── progress.md                    # 官方流程的阶段、下一步与关键记录
    ├── custom-workflow/               # 自定义流程的运行状态、事件与回执
    └── confirmed-artifacts/
        ├── catalog.json               # 确认版本的权威索引
        └── versions/                  # 已确认版本的不可变历史快照
```

例如，两份引言稿可能都保存在你的工作目录中，但索引会明确指出哪一份的哪个内容版本已经被采用。文件修改时间、文件名中的“最终版”，以及它是否位于某个下载目录，都不决定确认状态。

`current` 用于浏览当前成果，是可以重建的展示副本。程序通过索引解析时会校验并返回不可变快照，优先读取该快照；原来的工作路径继续保留，因为运行回执、图件来源和其他材料可能仍然引用它。

更新或撤下展示文件时，被替换的文件也会保留在内部的 `projection-backups/` 目录，避免与编辑器同时保存时丢失改动。这些展示备份与已确认的历史快照分别保存；备份本身不代表新的确认。

## 修改、确认与撤回

修改工作源文件后，先前确认的快照保持原样。你可以继续试写，在检查并采纳新版本后再更新当前版本。这让“正在修改的内容”和“目前认可的内容”保持清晰。

直接编辑 `artifacts/current/` 中的展示文件不会形成新的确认记录。如果确实在这里做了修改，应先把改动保留下来，作为工作候选版本重新检查。展示修复遇到这类改动时会报告冲突；只有明确同意保留改动备份并修复，才会重新生成展示。

如果已经采用的成果需要撤回，可以在对话中明确提出：“撤回这份结果的当前确认状态，保留历史版本。”撤回后，工作流不会自行把更早的版本重新当作当前版本；需要恢复旧版时，应明确选择并重新确认。

## 恢复会话时先读什么

继续一个已有项目时，最短阅读顺序是：

```text
项目模式摘要 → 当前模式的进度摘要 → 已确认产物索引 → 本次任务需要的具体材料
```

可以向 Codex 发送：

```text
继续这个论文项目。先检查当前使用的是官方流程还是自定义流程，
读取当前进度和已确认产物索引，告诉我下一步是什么、将使用哪些确认版本。
需要查证具体决定时再查相应记录。
```

官方流程读取 `progress.md` 中的当前状态和下一步。自定义流程读取运行管理器提供的节点状态与整体摘要。历史记录保留用于追溯，恢复会话时先取当前摘要，需要核对某项决定或来源时再展开相关历史。

索引摘要默认只读取记录，不修改文件，也不重新核对全部文件内容。实际使用某份成果前，解析操作会检查它的快照；需要排查展示完整性时，再明确检查当前展示文件。

## 怎样理解自定义流程的进展

自定义摘要把所有阶段按状态分组，并给出当前执行情况：

| 摘要状态 | 含义 |
|---|---|
| `ready` | 已记录的状态中有可以继续领取的阶段 |
| `running` | 有阶段正在执行 |
| `needs_attention` | 有失败、阻碍或内容已经过时的阶段需要处理 |
| `waiting` | 仍有阶段待推进，当前没有可直接继续的阶段 |
| `finished` | 所有阶段已经执行结束或被跳过 |
| `stopped` | 这轮运行已经停止 |
| `empty` | 没有可计数的阶段 |

摘要同时保留各状态的数量和阶段列表，因此 `running` 时也可能有其他阶段需要处理。计数包含条件和汇合等控制阶段；跳过会单独列出。

`finished` 表示阶段执行已经结束。论文是否通过科学审查、某份成果是否被你采用，需要分别查看验收记录与确认索引。

## 中断后的恢复

遇到断电、程序意外退出或运行状态需要恢复时，先确认旧的任务或验证器进程已经停止，再让 Codex 执行恢复。恢复会检查持久化记录，并将无法证明已经完成的中断任务留待处理。

恢复完成后不会自动运行任务。Codex 会先重新读取摘要，再根据实际状态重试失败阶段，或重新处理已过时的阶段。如果旧进程仍在工作，应先让它结束或明确停止；此时不能把它当成中断任务恢复。

## 多文件成果与自定义任务

LaTeX 稿件可能依赖图片和其他章节文件；图件可能同时包含矢量文件、预览、代码和检查记录。确认这类成果时，需要列出本次采纳的完整文件清单，快照会保留清单内的相对路径。工作流不会自动把清单之外的目录或外部依赖一起收集。

已确认快照与自定义运行回执分别记录不同事实。自定义任务仍按调用凭据中绑定的输入路径执行，包括后续新领取的任务；确认产物索引不会改写这些绑定。在另一轮自定义流程中使用确认快照时，Codex 应先解析确认版本，再把它登记为新流程已声明的外部输入。

## 常见情况

| 情况 | 处理方式 |
|---|---|
| 工作文件更新了，当前确认版本没有改变 | 检查新内容并明确采用，之后再登记新版本 |
| 产物已确认，但进度中的下一步尚未更新 | 核对当前进度并补记下一步，无需再次采纳同一成果 |
| 进度更新提示内容已变化 | 重新读取当前摘要，核对其他修改后再更新 |
| 读取确认版本时提示版本号已变化 | 重新查看索引，确认本次任务应该使用哪个版本 |
| 当前展示缺失，但确认记录仍在 | 通过修复操作从已确认快照重建展示 |
| 当前展示被手工改动 | 先保留改动作为候选或备份，再明确修复；不要直接覆盖它 |
| 旧工作路径变化导致自定义运行暂停 | 先处理该运行的输入或回执状态；已确认快照与该运行的恢复分别检查 |
| 历史快照校验失败 | 保留现场并检查损坏原因；展示副本不能自动替代确认事实 |

需要了解命令行接口、原子提交和恢复机制时，参阅[开发指南](../DEVELOPMENT_GUIDE.md)；请求字段与完整示例见[已确认产物合同](../references/confirmed-artifacts.md)。
