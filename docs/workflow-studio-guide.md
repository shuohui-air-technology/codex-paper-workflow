# Workflow Studio 入门指南

[返回文档导航](README.md) · [返回项目首页](../README.zh-CN.md)

Workflow Studio 用来安排论文项目中的阶段、每个阶段使用的 Skill，以及阶段之间传递的成果。你在浏览器里编辑并启用流程，再回到同一个项目的 Codex 对话中推进研究任务。

如果默认流程已经适合你的项目，直接在 Codex 中使用即可。本指南面向希望调整阶段顺序、替换 Skill 或建立独立小流程的使用者。

## 打开编辑器

先按[安装说明](../README.zh-CN.md#快速安装)安装工作流。本指南的三阶段示例使用 `standard` 配置中提供的 Skill。

准备一个存放论文材料的目录，例如“我的论文”。在终端中进入这个目录，然后运行：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/paper-workflow-orchestrator/scripts/workflow_studio.py" --project .
```

最后的 `.` 表示终端当前目录。浏览器打开后，核对页眉显示的项目名称。使用期间保持终端运行；结束编辑后，可以在启动它的终端按 `Ctrl+C` 关闭本地服务。长时间未操作导致会话结束时，重新运行同一条命令。

Windows 和自定义安装目录的启动方式见 [README 的自定义工作流入口](../README.zh-CN.md#自定义工作流编排)。

## 先认识界面

| 界面区域 | 用途 |
|---|---|
| 页眉中的当前模式 | 确认项目正在使用官方流程还是自定义流程 |
| 阶段工具 | 添加任务、条件、汇合和验证阶段 |
| 中间画布与阶段列表 | 查看先后关系、选择阶段、调整布局 |
| 阶段设置 | 修改名称、选择 Skill、配置输入和输出 |
| 流程设置 | 修改流程标识、并行数量和外部输入 |
| 验证结果 | 找出缺少 Skill、断开的阶段或未配置的输入 |

“任务”阶段由选定的 Skill 完成研究或写作。“验证”阶段检查已有文件。“条件”决定走哪条分支，“汇合”让前面的分支重新合并。第一次使用只需任务阶段，先把一条顺序流程跑通。

阶段名称、Skill、输入输出、条件和连接映射都在对应的常规设置区域中。“高级设置”收纳流程入口、失败处理、任务结果、写入范围与精确位置等选项。“撤销”和“重做”保留自上次保存以来的最多 50 次编辑，保存或重新载入后重新开始记录。“自动整理画布”调整卡片位置，阶段之间的连线决定先后关系。

## 建立第一个三阶段流程

下面的例子适合已有研究材料、希望整理文献并形成引言草稿的项目：

```text
整理文献 → 撰写引言 → 审查草稿
```

这三个阶段分别产出文献比较表、引言草稿和审查意见。请准备研究问题、自己的研究材料，以及准备比较的文献笔记或可核验来源；材料不足时，Codex 会先与你补齐当前任务所需的内容。

### 1. 创建草稿并命名

选择“新建空白流程”。打开“流程设置”，将流程标识改成 `introduction-review`，最大并行阶段数保持为 `1`，在“外部输入”中添加 `research_materials`。

外部输入是你将在运行时提供的材料名称。这里填写的是名称；实际文件由同一项目中的 Codex 对话读取并登记。例如，`research_materials` 可以对应你整理的研究说明与文献材料索引文件。

### 2. 设置第一阶段

选中空白流程中的第一个任务，将名称改为“整理文献”，主要 Skill 选择 `literature-triage-matrix`，在“高级设置”中保留“作为流程入口”。输入填 `research_materials`，输出填 `literature_matrix`。

“流程入口”表示从这里开始。这个例子只有第一阶段作为入口，后两阶段由上一阶段完成后触发。

### 3. 追加后续阶段

选中“整理文献”，将“新阶段添加位置”设为“接在所选阶段之后”，然后添加任务；再选中新阶段，继续追加第三个任务。按下表设置每一阶段：

| 阶段名称 | 主要 Skill | 输入产物 | 输出产物 |
|---|---|---|---|
| 整理文献 | `literature-triage-matrix` | `research_materials` | `literature_matrix` |
| 撰写引言 | `ml-paper-writing` | `literature_matrix`, `research_materials` | `introduction_draft` |
| 审查草稿 | `academic-paper-reviewer` | `introduction_draft` | `review_notes` |

`ml-paper-writing` 面向机器学习及相关研究写作。如果你的学科不同，可以选择更适合你的已安装写作 Skill；输入与输出仍按你希望交付的内容配置。

产物名称是阶段之间传递内容的标识。例如，上一步输出 `literature_matrix`，下一步输入也填 `literature_matrix`，它们就指向同一项成果。文件的实际相对路径在运行时登记，编辑器中的产物名称无需写成文件路径。

在“高级设置”中，三个阶段的“写入范围”可分别填 `literature_matrix`、`introduction_draft`、`review_notes`，让各阶段负责不同成果。保留任务结果 `succeeded` 和“失败时：阻止后续流程”。

### 4. 检查连接

确认画布上有两条顺序连接：整理文献到撰写引言、撰写引言到审查草稿；触发结果使用 `succeeded`，表示上一步成功后进入下一步。同名产物可以沿连接传递；此例无需改名映射。`research_materials` 已在流程设置中声明为外部输入，因此第二阶段也能使用它。

把阶段卡片拖近不会自动建立连接。若选择的是“独立添加，稍后连接”，需在“阶段连接”中选择前后阶段，或在画布上连接节点。可使用“自动整理画布”让这条顺序关系更容易阅读。已有多条出线的分支阶段需要独立添加任务，再明确选择要接入的分支。

本例逐次在流程末尾追加阶段。向两个已连接的阶段之间插入新阶段时，还要保留它们原有的产物传递；如果空白阶段会使后续输入失去来源，编辑器会阻止插入。此时选择独立添加，先配置新阶段的输入输出，再明确连接前后阶段，并验证数据如何传到下一步。

### 5. 验证与启用

先选择“验证流程”。发现问题时，点击“定位相关阶段”或提示中的“配置此阶段”，补齐 Skill、输入或连接，再验证一次。

尚未配置完也可以先“保存草稿”，下次从同一论文项目打开 Studio 后继续。准备使用时选择“验证并启用”，阅读并确认实际列出的风险提示。启用成功后，页眉会显示自定义流程已启用。

这个例子是一条局部写作流程。检查时会提示它省略了完整论文流程中的引用、实验、图件、完整性及终稿检查；引言草稿和审查意见是本例的交付目标，完整论文交付仍需安排相应检查。

### 6. 回到 Codex 推进任务

选择“复制继续执行提示词”，将提示词发到同一论文项目的 Codex 对话。也可以直接发送：

```text
使用 paper-workflow-orchestrator 继续我在这个项目中已启用的自定义工作流。
先检查当前模式和可执行阶段，告诉我 research_materials 需要对应哪份材料，并引导我登记外部输入。
这次的目标是根据已有研究内容整理文献、撰写引言并审查草稿。请逐阶段推进，完成当前阶段后说明产物和下一步。
```

Studio 负责编辑和选择流程，Codex 负责调用 Skill、处理研究材料并登记结果。成功启用表示流程已准备好供 Codex 推进；实际生成文献表或草稿发生在后续对话中。

## 在官方流程基础上修改

需要保留大部分完整论文流程时，选择“复制为自定义流程”。复制后，页眉仍能显示当前启用的是官方流程，同时提示正在编辑自定义草稿。先调整少量阶段，例如替换写作 Skill、插入审查任务，再验证整条流程。

删除或停用阶段后，要重新检查它的后续阶段是否仍能获得输入。只需临时排除某一步时可以停用；确定不再需要时再删除。复制出的流程同样要通过验证并启用，才会成为 Codex 的执行依据。

## 草稿与当前流程

| 当前操作 | 保存在哪里 | 对当前运行的影响 |
|---|---|---|
| 在浏览器中编辑，尚未保存 | 当前编辑会话 | 当前运行版本保持不变 |
| 保存草稿 | 论文项目的自定义工作流目录 | 下次可继续编辑，当前运行版本保持不变 |
| 验证并启用 | 记录已验证的流程版本并建立运行状态 | Codex 后续按该自定义版本推进 |
| 切回官方流程 | 保留已保存的自定义草稿 | 停止当前自定义运行，后续按官方流程推进 |

运行中的自定义版本固定对应启用时的配置。修改并保存草稿后，如需采用新版本，先确认当前阶段的工作已妥善处理，再切回官方流程并重新验证、启用新草稿。重新启用会建立新的运行状态，不会自动承接上一轮的阶段进度。

关闭浏览器前留意“有未保存修改”。同一项目在多个窗口同时编辑时，如果出现版本冲突，可以先下载当前浏览器草稿的备份，再载入服务器最新草稿，重新核对你的改动。

## 进一步编排

| 需求 | 建议做法 |
|---|---|
| 换一个负责当前任务的 Skill | 选中阶段，在主要 Skill 列表中选择一项已安装能力 |
| 检查已有成果 | 独立添加验证阶段，配置上游输入角色和检查后的连接；保留后续任务需要的产物来源 |
| 根据结果决定下一步 | 添加条件阶段，在表单中设置判断规则和分支；为未匹配情况保留默认路径 |
| 同时完成互不冲突的任务 | 连接到多个任务，设置合适的最大并行阶段数，为任务声明不重叠的写入范围 |
| 等待多个任务完成后再继续 | 添加汇合阶段，并按需要选择等待全部分支或任一成功 |

验证器检查已有成果，结果会写入检查记录。按表单指定输入产物和论文类型、语言等参数即可；可选列表中的 Humanizer Preflight 在首版自定义流程中不可用。

验证阶段没有文件输出，也不会自动转发上一步的产物。如果在已有两步之间增加检查，后一步需要的文件仍应从实际生成它的阶段传入；检查结果通过 `pass`、`fail` 或 `blocked` 连接安排后续走向。配置后同时验证产物来源与检查未通过时的处理方式。

并行与条件分支会增加输入来源和完成条件的复杂度。建议先验证顺序流程，再逐一添加这些安排；每次变更后检查产物来源和失败时的后续路径。

## 问题排查

| 现象 | 如何处理 |
|---|---|
| 浏览器没有自动打开 | 从终端启动记录中复制完整的 `url` 地址到浏览器，包含 `#session=` 后的部分 |
| 页面提示会话失效或连接失败 | 检查启动终端是否仍在运行；重新启动 Studio，并使用新的页面地址 |
| 打开了错误的项目 | 关闭当前服务，在正确的论文目录运行命令，或给 `--project` 传入该目录的完整路径 |
| Skill 列表缺少需要的能力 | 确认已安装相应配置；此例需要 `standard`。使用自定义 Codex 主目录时，在启动 Studio 的终端设置同一 `CODEX_HOME`；安装完成后重新启动 Studio |
| 验证提示没有绑定 Skill | 选中对应任务，在“主要 Skill”中选择一项可用能力 |
| 验证提示缺少输入来源 | 检查上一步是否输出同名产物、是否有连接；由用户提供的材料需在“外部输入”中声明 |
| 新增阶段没有接入流程 | 检查连线。“独立添加，稍后连接”用于单独放置节点；顺序流程可以选择“接在所选阶段之后” |
| 插入阶段被阻止，提示会破坏产物传递 | 独立添加新阶段，先配置输入输出，再调整连接并重新验证；验证阶段的检查记录不能替代后续任务需要的文件输入 |
| 保存后运行还是旧版本 | 保存只更新草稿。按上文的切换步骤验证并启用新版本 |
| 保存或启用被版本冲突锁定 | 先保留浏览器草稿备份，再载入服务器最新草稿并重新核对 |
| 已启用，但没有生成论文文件 | 回到同一项目的 Codex 对话，发送继续提示词，并提供当前阶段所需材料 |

需要了解字段含义或精确执行规则时，继续阅读[自定义工作流合同](../references/custom-workflow-contract.md)。准备修改程序时，阅读[开发指南](../DEVELOPMENT_GUIDE.md)。
